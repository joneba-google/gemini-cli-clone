## Commit Message

[SSR Agent] Issue Fix (20635): Require toolName property on policy rules to avoid catch-all

## PR Description

fixes #20635
Original Issue: https://github.com/google-gemini/gemini-cli/issues/20635

### Context & Problem
Policy rules and safety checker rules without a `toolName` property implicitly acted as catch-all rules matching all tools unconditionally. This was caused by `toolName` being optional in the Zod schemas and TypeScript interfaces, allowing typos or omitted fields to bypass security constraints and inadvertently grant excessive tool permissions.

### Detailed Changes
- **Type Definitions**: Updated `PolicyRule` and `SafetyCheckerRule` interfaces in [types.ts](file:///usr/local/google/home/joneba/ssr-prototype/gcli-intern-project/tools/caretaker-agent/evals/pr-generation/run_outputs/test_large_golden_3.5_flash/agent_environments/gemini_cli_20635/tmp/eval/gemini-cli/packages/core/src/policy/types.ts) and the `McpContext.getPolicyEngine` return type in [mcp-client.ts](file:///usr/local/google/home/joneba/ssr-prototype/gcli-intern-project/tools/caretaker-agent/evals/pr-generation/run_outputs/test_large_golden_3.5_flash/agent_environments/gemini_cli_20635/tmp/eval/gemini-cli/packages/core/src/tools/mcp-client.ts) to make `toolName` a required string.
- **Schema Validation**: Modified `PolicyRuleSchema` and `SafetyCheckerRuleSchema` in [toml-loader.ts](file:///usr/local/google/home/joneba/ssr-prototype/gcli-intern-project/tools/caretaker-agent/evals/pr-generation/run_outputs/test_large_golden_3.5_flash/agent_environments/gemini_cli_20635/tmp/eval/gemini-cli/packages/core/src/policy/toml-loader.ts) to make `toolName` required. Implemented validation in `loadPoliciesFromToml` to reject policy and safety checker rules that specify an empty string for `toolName`.
- **Policy Engine**: In [policy-engine.ts](file:///usr/local/google/home/joneba/ssr-prototype/gcli-intern-project/tools/caretaker-agent/evals/pr-generation/run_outputs/test_large_golden_3.5_flash/agent_environments/gemini_cli_20635/tmp/eval/gemini-cli/packages/core/src/policy/policy-engine.ts), added constructor validations requesting non-empty, non-undefined `toolName` properties. Refactored the `ruleMatches` function to explicitly support wildcard matching (`'*'`) and ensure correct matching logic.
- **Configuration & Policies**: Updated built-in templates ([yolo.toml](file:///usr/local/google/home/joneba/ssr-prototype/gcli-intern-project/tools/caretaker-agent/evals/pr-generation/run_outputs/test_large_golden_3.5_flash/agent_environments/gemini_cli_20635/tmp/eval/gemini-cli/packages/core/src/policy/policies/yolo.toml), [plan.toml](file:///usr/local/google/home/joneba/ssr-prototype/gcli-intern-project/tools/caretaker-agent/evals/pr-generation/run_outputs/test_large_golden_3.5_flash/agent_environments/gemini_cli_20635/tmp/eval/gemini-cli/packages/core/src/policy/policies/plan.toml), and YOLO config in [config.ts](file:///usr/local/google/home/joneba/ssr-prototype/gcli-intern-project/tools/caretaker-agent/evals/pr-generation/run_outputs/test_large_golden_3.5_flash/agent_environments/gemini_cli_20635/tmp/eval/gemini-cli/packages/a2a-server/src/config/config.ts)) to use `toolName = "*"` for wildcard behavior.
- **Tests**: Adjusted engine/loader test files to conform to the schema changes and added comprehensive tests verifying validation error scenarios for missing or malformed `toolName` inputs.
